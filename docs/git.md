# Git-first: git carries the code, Kitebook is the control plane

Claude.ai, ChatGPT and Hark all read GitHub through their own connectors, so Kitebook never becomes a code host:
- **Tasks reference code by git.** `task_create` takes optional `repo` (a git remote URL such as `https://github.com/o/r`, or the runner's project name) and `base` (branch, tag or commit; default the checkout's HEAD, fetched from the remote when it isn't local). The server maps a remote URL to the runner project whose `origin` it is (`describe` and `shared/runners/<runner>.json` list each project's `remote`) and refuses an unknown repo or a malformed base at create time.
- **Results always say where the work is.** `result.structured` (and `git.json`) carry `branch` (`kitebook/<task id>`), `base` (the commit it branched from), `commit` (head), `diff_stat` `{files, insertions, deletions}` against base, `pushed`, and `compare_url` (`https://github.com/o/r/compare/<base>...<branch>`, when pushed to GitHub) plus `pr_url`. `inbox` → `finished` carries `commit` and `compare_url` too.
- **Changesets: code an assistant wrote never sits loose in the space.** `change {target, project|repo, base, message, diff | files, slug?}` stores a unified diff or a `{path: content | null}` file set as a task; the runner (after the usual approval) applies it in a fresh worktree at `base`, commits it on `<assistant>/<slug>` (`hark/fix-login`; a taken name gets a suffix) with the assistant as author, runs `verify` if given, and pushes only that branch per the project's push policy. A diff that doesn't apply is a `conflict` (status `conflict`, `conflict {base, files, output}` from `git apply --check`): the worktree and branch are dropped, never half-applied. Protected files (AGENTS.md, CI workflows...) are refused. `write`/`batch` of code-like files outside `kb/` and `shared/notes/` return `warning: "code_outside_change"`.
- **Done means committed.** A coding task can't finish `succeeded` with a dirty worktree: the runner commits whatever the agent left (as `wip: ...` when the agent made its own commits) on the task branch and pushes per policy. The result carries `committed`, `pushed`, `dirty_left`, `no_changes` (explicit "no changes" in the summary/headline) and `wip_commit`; if a commit fails (e.g. a hook), the task fails with `dirty_left` and the worktree is kept.
- **Sync status.** The runner reports each project's git state (branch, `dirty` count, `ahead`/`behind` upstream, default branch, assistant branches `hark/* claude/* chatgpt/* kitebook/*` on origin that aren't merged, with whether they're pulled locally) every minute, and runs `git fetch --prune` every `fetchEvery` seconds (default 600). `code_status` (op + MCP tool) returns it with `notes` ("assistant branch hark/x not pulled locally", "local has uncommitted work: 3 file(s) on main", "main is 2 commit(s) behind origin/main"); `peers` shows a one-line `code` summary per runner. The runner never touches your checkout, except: with `"autoFastForward": true` (runner.json, global or per project; default off) a clean checkout that is only behind its upstream is fast-forwarded.
- **Pushes are the task branch only, never main.** A runner pushes nothing but `kitebook/<task id>` (`main`/`master`/the base branch are refused even if a follow-up somehow pointed there), and `destructiveGuard` blocks agents pushing main themselves.
- **Kitebook holds live state only**: tasks, status, approvals, questions, results and a small `shared/` scratchpad. Retention (Space DO alarm, daily) prunes finished tasks older than 30 days with their `tasks/<id>/` files (history included) and events, drops events older than the window, and garbage-collects blobs nothing references any more (R2/S3 objects too). Active tasks, `shared/` and other files, members and grants are kept. Configure with `RETENTION_DAYS` (0 = keep forever) or per space: `bun client/admin.ts retention <space> [days]`; `bun client/admin.ts prune <space> [older_than_sec]` runs it now. The upcoming live KB (its own `kb_*` tables) is never pruned.

## Git integration (per project in runner.json)
- `"push": "ask"` asks you again locally before pushing `kitebook/<task-id>` to `"remote"` (default `origin`). The remote can be GitHub, Gitea/Forgejo, or any bare repo. `"never"` is the default, and `"auto"` skips the prompt.
- `"pr": true` (the default): if the remote is GitHub, the runner opens a **draft PR** with `gh` after pushing. Nothing gets merged automatically.
- `"mirror": true` (opt-in per project, **off by default**, including for auto-discovered repos) keeps `repos/<project>/` in the space identical to your checkout, for assistants that can't reach the git host. Until some runner opts a project in, the mirror and its `has` op aren't advertised (guide, llms.txt, MCP tools/list); `describe` shows `mirror` once it's on:
  - It includes tracked and untracked files but skips `.gitignore`d ones, `.env`, keys, and anything the secret guard refuses.
  - Every `mirrorEvery` seconds (default 30), it sends only the changed files. Files whose size/mtime/inode didn't change since the last scan aren't even read (stat cache in the mirror state file), so an idle scan costs one `git ls-files` and a stat per file. It asks the server which contents it already has (`has`) and sends just the new ones, in batches of up to 200 files.
  - `repos/<project>/.relay-repo.json` records the branch and commit.
  - The runner token needs `read,write,delete` on `repos/**`.
- Git stays the source of truth for code. The server carries tasks, results and a read copy, and it never becomes a git server.
